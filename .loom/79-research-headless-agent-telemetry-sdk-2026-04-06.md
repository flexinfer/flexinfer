# Research: Headless Agent Driving & SDK-Based Telemetry Mapping

**Date:** 2026-04-06
**Scope:** Platform feature improvements for driving headless Claude and Codex agents via web HUD and mobile app, with structured telemetry mapping from each CLI SDK's event model to Loom's canonical model.

---

## 1. Current State

### How Loom Drives Headless Agents Today

All three agent types (Claude Code, Codex, Gemini) are invoked as **opaque CLI subprocesses** inside K8s pods via the `SpawnOrchestrator` (`internal/hud/spawn.go`).

| Agent | CLI Command | Output Capture |
|-------|------------|----------------|
| Claude Code | `claude -p <task> --dangerously-skip-permissions --output-format json --max-turns 50` | `StdoutTail` (last 8KB, stored as context entry) |
| Codex | `codex exec --full-auto --json <task>` | `StdoutTail` (last 8KB) |
| Gemini | `gemini -p <task> --yolo` | `StdoutTail` (last 8KB) |

**Ref:** `internal/hud/spawn.go:441–452` (`buildAgentCommand()`), `internal/hud/spawn.go:338–350` (output capture).

### What's Lost

Both Claude and Codex emit **rich typed JSON event streams** during execution. Today Loom discards all of this:

| SDK Event | Claude Agent SDK | Codex SDK | Loom Capture Today |
|-----------|-----------------|-----------|-------------------|
| Per-turn token usage | `AssistantMessage.message.usage` | `turn.completed.usage` | **None** |
| Total cost | `ResultMessage.total_cost_usd` | Not emitted | **None** |
| Tool calls (name, duration, result) | `AssistantMessage.content[tool_use]` + `UserMessage[tool_result]` | `item.completed{type:command_execution}` | **None** |
| File changes | Inferred from `Write`/`Edit` tool calls | `item.completed{type:file_change}` | **None** |
| Agent reasoning | `AssistantMessage.content[thinking]` | `item.completed{type:reasoning}` | **None** |
| Error/failure details | `ResultMessage.subtype: error_*` | `turn.failed` / `item{type:error}` | Exec exit code only |
| MCP tool calls | `AssistantMessage.content[tool_use]` (prefixed `mcp__`) | `item.completed{type:mcp_tool_call}` | **None** |
| Session ID | `ResultMessage.session_id` | `thread.started.thread_id` | External only (Loom creates its own) |
| Subagent activity | `SDKTaskStartedMessage`, `SDKTaskProgressMessage` | `spawn_agent` / `wait_agent` tool calls | **None** |
| Rate limit events | `SDKRateLimitEvent` | Not emitted | **None** |

### How Hooks Map Today (Non-Spawned Agents)

For interactive (non-spawned) agents, CLI hooks bridge events to Loom:

| Field | Claude Code | Codex | Gemini |
|-------|------------|-------|--------|
| `session_start` | SessionStart hook | Lazy via heartbeat `--ensure-session` | SessionStart hook (generated) |
| `session_end` | Stop hook | **Never** (sessions leak) | SessionEnd hook (generated) |
| `heartbeat` | PostToolUse(Bash\|Task) + keepalive | notify (1/15s) | AfterTool(run_shell_command) |
| `task_sync` | PostToolUse(TaskCreate\|TaskUpdate) | **Never** | **Never** |
| `active_files` | **Not sent** | **Not sent** | **Not sent** |
| `branch` | **Not sent** | **Not sent** | **Not sent** |
| `current_task` | **Not sent** | **Not sent** | **Not sent** |

**Ref:** `.claude/settings.json`, `.codex/config.toml`, `.gemini/settings.json` (all generated by `loom sync`).

## 2. SDK Capabilities Assessment

### Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`)

**Package:** Renamed from `@anthropic-ai/claude-code`. Pinned version in loom: `1.0.33`.

**V1 API — `query()` async generator:**
```typescript
for await (const message of query({
  prompt: task,
  options: {
    allowedTools: ["Read", "Edit", "Bash"],
    maxTurns: 50,
    maxBudgetUsd: 5.00,
    permissionMode: "acceptEdits",
    model: "claude-sonnet-4-6",
    settingSources: ["project"],  // loads CLAUDE.md, skills, hooks
    includePartialMessages: true, // streaming deltas
  }
})) {
  // Typed SDKMessage union: assistant, result, system, hook_*, task_*, stream_event, ...
}
```

**Key types for telemetry mapping:**

| SDK Type | Key Fields | Maps to Loom |
|----------|-----------|--------------|
| `SDKAssistantMessage` | `uuid`, `session_id`, `message.usage{input_tokens,output_tokens}`, `message.content[tool_use\|text\|thinking]` | `TimelineEntry{agent.turn}`, token accounting |
| `SDKResultMessage` | `session_id`, `duration_ms`, `num_turns`, `total_cost_usd`, `usage`, `modelUsage`, `subtype` | `SessionInfo` enrichment, cost tracking |
| `SDKToolUseSummaryMessage` | Tool call summary | `TimelineEntry{agent.tool_call}` |
| `SDKTaskStartedMessage` / `SDKTaskProgressMessage` | Subagent lifecycle | Loom task/session hierarchy |
| `SDKRateLimitEvent` | Rate limit info | `TimelineEntry{agent.rate_limit}`, alerting |
| `SDKHookResponseMessage` | Hook execution result | Loom hook telemetry |

**In-process hooks (SDK-only, not CLI):**
- `PreToolUse` / `PostToolUse` — can intercept, modify, or block tool calls
- `Stop` — session termination
- `SubagentStart` / `SubagentStop` — parent-child session linking
- `PermissionRequest` — programmatic approval decisions

**V2 API — `createSession()` / `resumeSession()` (unstable preview):**
- Multi-turn sessions with `send()` / `stream()`
- Session persistence and forking

**Ref:** https://platform.claude.com/docs/en/agent-sdk/overview

### Codex SDK (`@openai/codex-sdk`)

**Package:** `@openai/codex-sdk` (separate from the CLI `@openai/codex`). Pinned CLI version in loom: `0.1.2025062000`.

**Core API — `Codex` client + `Thread`:**
```typescript
const codex = new Codex({ apiKey: process.env.OPENAI_API_KEY });
const thread = codex.startThread({ sandboxMode: "workspace-write" });

// Buffered
const turn = await thread.run(task);
// turn.finalResponse, turn.items, turn.usage

// Streaming
const { events } = await thread.runStreamed(task);
for await (const event of events) { /* ThreadEvent union */ }
```

**Key types for telemetry mapping:**

| SDK Type | Key Fields | Maps to Loom |
|----------|-----------|--------------|
| `ThreadStartedEvent` | `thread_id` | External session ID correlation |
| `TurnCompletedEvent` | `usage{input_tokens,cached_input_tokens,output_tokens}` | Token accounting |
| `ItemCompletedEvent{type:command_execution}` | `command`, `stdout`, `stderr`, `exit_code` | `TimelineEntry{agent.tool_call}` |
| `ItemCompletedEvent{type:file_change}` | `changes[{kind,path}]` | File claim tracking, diff capture |
| `ItemCompletedEvent{type:agent_message}` | `text` | Agent output |
| `ItemCompletedEvent{type:mcp_tool_call}` | `server`, `tool`, `arguments`, `result` | MCP tool telemetry |
| `ItemCompletedEvent{type:reasoning}` | `text` | Context entry (optional) |
| `TurnFailedEvent` | Error info | `TimelineEntry{agent.error}` |

**Multi-agent native tools:** `spawn_agent`, `wait_agent`, `send_input`, `resume_agent`, `close_agent` — these are model-invoked tools, not SDK methods. They create subthreads visible in the event stream.

**MCP server mode:** `codex mcp-server` exposes `codex` and `codex-reply` tools for external orchestration.

**Ref:** https://developers.openai.com/codex/sdk

## 3. Canonical Model Gaps

### Loom's Canonical Model (Current)

**Ref:** `internal/hud/bridge/agent_dto.go`

```
SessionInfo     — id, agent_id, namespace, project, status, description, entry_count, total_tokens
PresenceInfo    — agent_id, session_id, status, agent_type, description, current_task, active_files, branch
TaskInfo        — id, session_id, agent_id, title, status, priority, tags, blocked_by
TimelineEntry   — timestamp, event_type, agent_id, agent_type, data (raw JSON)
```

### Missing Fields for SDK-Driven Telemetry

| Gap | Description | Needed For |
|-----|-------------|------------|
| **Per-turn token usage** | Input/output/cache tokens per turn, not just session total | Token economics panel, cost monitoring |
| **Cost tracking** | `total_cost_usd`, per-model breakdown | Budget enforcement, ROI metrics |
| **Tool call log** | Structured tool name + args + result + duration | Tool latency waterfall, debugging |
| **File change tracking** | Structured list of files modified by agent | File conflict detection, diff preview |
| **External session/thread ID** | Claude `session_id` / Codex `thread_id` | Session correlation, resumption |
| **Agent output stream** | Real-time typed events, not just final `StdoutTail` | Live HUD/mobile progress |
| **Subagent tree** | Parent → child session hierarchy | Multi-agent topology view |
| **Error classification** | Typed error: `max_turns`, `max_budget`, `rate_limit`, `execution_error` | Alert routing, auto-retry |
| **Rate limit events** | When/why agent was throttled | Capacity planning, alerting |

### Proposed Canonical Extensions

```go
// SpawnTelemetry extends spawn state with SDK-sourced structured telemetry.
type SpawnTelemetry struct {
    ExternalSessionID string              `json:"external_session_id,omitempty"` // claude session_id or codex thread_id
    TurnCount         int                 `json:"turn_count"`
    TotalCostUSD      float64             `json:"total_cost_usd"`
    TokenUsage        SpawnTokenUsage     `json:"token_usage"`
    ModelUsage        map[string]ModelUse `json:"model_usage,omitempty"`       // per-model breakdown (claude)
    ToolCalls         []ToolCallEntry     `json:"tool_calls,omitempty"`        // structured tool log
    FileChanges       []FileChangeEntry   `json:"file_changes,omitempty"`      // files touched
    Errors            []AgentError        `json:"errors,omitempty"`            // typed errors
    StopReason        string              `json:"stop_reason,omitempty"`       // end_turn, max_turns, max_budget, error
}

type SpawnTokenUsage struct {
    InputTokens             int `json:"input_tokens"`
    OutputTokens            int `json:"output_tokens"`
    CacheCreationTokens     int `json:"cache_creation_tokens"`
    CacheReadTokens         int `json:"cache_read_tokens"`
}

type ModelUse struct {
    CostUSD      float64 `json:"cost_usd"`
    InputTokens  int     `json:"input_tokens"`
    OutputTokens int     `json:"output_tokens"`
}

type ToolCallEntry struct {
    Name       string `json:"name"`
    ServerName string `json:"server_name,omitempty"`  // for MCP tools
    DurationMs int    `json:"duration_ms,omitempty"`
    ExitCode   *int   `json:"exit_code,omitempty"`    // for command_execution
    Error      string `json:"error,omitempty"`
    Timestamp  string `json:"timestamp"`
}

type FileChangeEntry struct {
    Path string `json:"path"`
    Kind string `json:"kind"` // create, modify, delete
}

type AgentError struct {
    Type    string `json:"type"`    // max_turns, max_budget, rate_limit, execution, tool_failure
    Message string `json:"message"`
    Time    string `json:"time"`
}
```

## 4. SDK Event → Loom Canonical Mapping Tables

### Claude Agent SDK → Loom

| SDK Event | Loom Target | Transform |
|-----------|-------------|-----------|
| `SDKAssistantMessage.message.usage` | `SpawnTelemetry.TokenUsage` (accumulate) | Sum input/output tokens |
| `SDKAssistantMessage.message.content[tool_use]` | `SpawnTelemetry.ToolCalls[]` | Extract name, track start time |
| `SDKUserMessage[tool_result]` | `SpawnTelemetry.ToolCalls[].DurationMs` | Match by tool_use_id, compute delta |
| `SDKResultMessage.total_cost_usd` | `SpawnTelemetry.TotalCostUSD` | Direct map |
| `SDKResultMessage.modelUsage` | `SpawnTelemetry.ModelUsage` | Direct map |
| `SDKResultMessage.num_turns` | `SpawnTelemetry.TurnCount` | Direct map |
| `SDKResultMessage.subtype` | `SpawnTelemetry.StopReason` | Map: `success`→`end_turn`, `error_max_turns`→`max_turns`, etc. |
| `SDKTaskStartedMessage` | `TimelineEntry{agent.subagent.start}` | Broadcast to SSE |
| `SDKRateLimitEvent` | `SpawnTelemetry.Errors[]` + `TimelineEntry{agent.rate_limit}` | Type=rate_limit |
| `SDKToolUseSummaryMessage` | `TimelineEntry{agent.tool_summary}` | Direct |
| Any `SDKMessage` | `TimelineEntry` (agent_id-scoped) | Real-time SSE broadcast |

### Codex SDK → Loom

| SDK Event | Loom Target | Transform |
|-----------|-------------|-----------|
| `ThreadStartedEvent.thread_id` | `SpawnTelemetry.ExternalSessionID` | Direct map |
| `TurnCompletedEvent.usage` | `SpawnTelemetry.TokenUsage` (accumulate) | Sum; map `cached_input_tokens` → `CacheReadTokens` |
| `ItemCompletedEvent{command_execution}` | `SpawnTelemetry.ToolCalls[]` | Name=`Bash`, extract command/exit_code |
| `ItemCompletedEvent{file_change}` | `SpawnTelemetry.FileChanges[]` | Direct map of changes[] |
| `ItemCompletedEvent{mcp_tool_call}` | `SpawnTelemetry.ToolCalls[]` | ServerName from server field |
| `ItemCompletedEvent{agent_message}` | Agent output text | Broadcast to SSE |
| `ItemCompletedEvent{reasoning}` | `TimelineEntry{agent.reasoning}` (optional) | Privacy-gated |
| `TurnFailedEvent` | `SpawnTelemetry.Errors[]` | Type=execution |
| `ThreadErrorEvent` | `SpawnTelemetry.Errors[]` + stop | Type=fatal |

### Gemini → Loom (CLI-only, no SDK available)

Gemini has no TypeScript SDK for programmatic driving. Continue using `gemini -p --yolo` with `StdoutTail` capture. Enrich via hook improvements only.

## 5. Architecture Options for SDK Integration

### Option A: Go sidecar process reads JSONL from agent stdout (recommended)

```
K8s Pod
┌─────────────────────────────────────────────┐
│  Agent CLI process (claude/codex)           │
│    stdout: JSONL events ──┐                 │
│                           │                 │
│  Go event parser goroutine│◄────────────────│
│    ├─ parse typed events  │                 │
│    ├─ accumulate telemetry│                 │
│    ├─ broadcast to HUD SSE│                 │
│    └─ store in SpawnState │                 │
└─────────────────────────────────────────────┘
         │
         ▼ (HTTP/SSE)
    HUD ←──── SpawnTelemetry
```

**How it works:**
1. Replace `backend.Exec()` (blocking, captures only tail) with a **streaming exec** that pipes stdout line-by-line to a Go parser goroutine
2. Each JSONL line is parsed into the appropriate SDK event type
3. Events are mapped to `SpawnTelemetry` fields and broadcast as `TimelineEntry` events via SSE
4. On completion, the final `SpawnTelemetry` is persisted to spawn state

**Pros:** Pure Go, no Node.js dependency in the sidecar, works with existing K8s exec API, minimal pod changes.

**Cons:** Must maintain Go parsers for two different JSONL schemas (Claude + Codex). No access to SDK-only features (hooks, session forking).

### Option B: Node.js sidecar using SDK libraries

```
K8s Pod
┌─────────────────────────────────────────────┐
│  Node.js driver process                     │
│    import { query } from "@anthropic-ai/    │
│      claude-agent-sdk"                      │
│    for await (const msg of query({...})) {  │
│      // typed events with full SDK access   │
│      POST http://localhost:9999/event        │
│    }                                        │
│                                             │
│  Go event collector (port 9999)             │
│    ├─ receive typed events                  │
│    ├─ accumulate telemetry                  │
│    └─ broadcast to HUD SSE                  │
└─────────────────────────────────────────────┘
```

**How it works:**
1. A small Node.js driver script imports the SDK and calls `query()` (Claude) or `thread.runStreamed()` (Codex)
2. Each typed message is POSTed to a local Go HTTP listener in the pod
3. The Go listener maps events to Loom's canonical model

**Pros:** Full SDK access (hooks, session management, structured output, MCP server control). Type-safe event handling. Access to `SDKToolUseSummaryMessage`, `SDKRateLimitEvent`, and other SDK-only events.

**Cons:** Adds Node.js runtime dependency to the pod. More complex pod setup. Two processes to manage.

### Option C: Hybrid — JSONL parsing + selective SDK usage

Use **Option A** (Go JSONL parsing) for the common path, but add a thin Node.js **SDK driver** for features that require programmatic SDK access:

- **JSONL parsing (Go):** Token usage, tool calls, file changes, errors, completion status — all available in `--output-format stream-json` (Claude) and `--json` (Codex)
- **SDK driver (Node.js):** Session forking, multi-turn orchestration, in-process hook callbacks, structured output schemas, MCP server hot-swapping

This lets us ship JSONL-based telemetry immediately (Slice 1-3) and add SDK-based orchestration incrementally (Slice 4+).

### Recommendation: Option C (Hybrid)

Start with pure Go JSONL parsing for telemetry (fast to ship, no new deps). Add SDK driver when we need multi-turn orchestration or in-process hooks. The JSONL schemas are stable enough — Claude's `--output-format stream-json` and Codex's `--json` both produce well-defined JSONL.

## 6. Feature Gap Analysis for HUD/Mobile Headless Driving

### Web HUD Gaps

| Feature | Current State | Needed |
|---------|--------------|--------|
| Live agent output | No streaming; see result only after completion | Real-time SSE events from spawn |
| Token usage | Not visible during/after spawn | Per-turn and cumulative token counters |
| Cost tracking | Not visible | Running cost counter, budget enforcement |
| Tool call log | Not visible | Timeline of tool calls with names/durations |
| File diff preview | Not visible | List of files changed with diff links |
| Error classification | Generic "failed" status | Typed error with max_turns/budget/rate_limit |
| Multi-turn control | Single-shot `claude -p` only | Send follow-up messages to running agent |
| Agent interruption | `spawn/{id}/stop` kills pod | Graceful interrupt via SDK `interrupt()` |
| Subagent tree | Flat agent list | Parent-child session hierarchy |

### Mobile App Gaps

| Feature | Current State | Needed |
|---------|--------------|--------|
| Spawn monitoring | `GET /api/mobile/v1/agents` (unified view) | Add `telemetry` field to `unifiedAgent` DTO |
| Live progress | SSE stream available but no spawn events | Spawn event types in SSE stream |
| Cost alerts | Not implemented | Push notification when cost threshold exceeded |
| Approval gates | Not applicable (full-auto) | Optional approval via push notification + mobile API |
| Output preview | Not available | Last N agent messages in mobile dashboard |

### Codex-Specific Gaps

| Gap | Impact | Fix |
|-----|--------|-----|
| No session-end hook | Sessions leak until 72h prune | Add `SessionEnd` equivalent via notify + `at_exit` trap |
| No task-sync | Codex internal tasks invisible to Loom | Parse `item.completed{type:todo_list}` from JSONL |
| No MCP proxy in spawned pods | Spawned Codex can't use Loom tools | Inject full `config.toml` with `[mcp_servers.loom]` |
| No parent-child session linking | Multi-agent Codex threads untracked | Parse `spawn_agent`/`wait_agent` items from JSONL |
| Minimal config injection | Only `[agent]\napproval = "auto-edit"` | Full config with sandbox, MCP, features |

## 7. Prior Art in Codebase

### EventConsumer Pattern (reusable for JSONL parsing)

The `bridge/events.go` `EventConsumer` already parses SSE events from the daemon with reconnect backoff. The same pattern applies to parsing JSONL from agent stdout — line-oriented, typed event dispatch.

**Ref:** `internal/hud/bridge/events.go:1–120`

### Agent Context Telemetry Store (reusable for spawn telemetry)

`internal/hud/agent_context_telemetry.go` already has `AgentContextTelemetrySnapshot` with per-agent-type metrics, Prometheus counters, and SSE broadcast. Extend this for spawn telemetry rather than creating a new subsystem.

**Ref:** `internal/hud/agent_context_telemetry.go`

### Spawn Controller State (extend, don't replace)

`internal/spawn/controller.go` already persists spawn state to `FileStore` + reconciles from K8s pod labels. The `SpawnTelemetry` struct should be added as a field on `spawn.State`, not a parallel store.

**Ref:** `internal/spawn/controller.go`
