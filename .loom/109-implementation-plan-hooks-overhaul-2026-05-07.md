# Implementation plan: agent-context hooks overhaul + CI session-linking

Date: 2026-05-07
Status: draft / not yet executed

## Problem

The current Claude Code / Gemini / Codex hooks emit lifecycle events to the loom
daemon for session tracking, presence, and task-sync, but they have accumulated
several reliability, performance, and observability problems that the user wants
addressed in one focused effort:

1. **Hooks are large inline shell strings (600–1969 chars each)** in
   `~/.claude/settings.json`, generated by `pkg/generator/configs_hooks.go`.
   The same agent-ID derivation, namespace inference, and log-redirect
   boilerplate is duplicated across SessionStart × 5, Stop × 2, SubagentStart
   × 1, PreToolUse × 3, PostToolUse × 6 — 17 hooks total. Hard to read,
   hard to debug, hard to extend.
2. **Failures are silent (`|| true` everywhere)**. There is no structured
   record of hook invocations, durations, or exit codes. When a hook quietly
   fails, the user only finds out because presence / session-linking stops
   working.
3. **No tracing or per-hook timing**. A slow hook delays Claude Code; we
   can't measure which hooks are the worst offenders without manually
   instrumenting `${TMPDIR:-/tmp}/loom-agent-hooks.log`.
4. **CI notifications exist but are not linked to sessions/agents
   intelligently.** `internal/hud/domain/webhook/{handlers,mapper}.go`
   handles `POST /api/webhook/{gitlab,github}` and, on a failed pipeline,
   maps to a `spawn.Request` that always launches a *fresh* `claude-code`
   agent. There is no logic to find the original commit author's currently-
   running agent session and notify it directly, even though
   `agent_presence_list` + the AgentBridge both have enough metadata
   (`AgentID` + `Branch` + `LastCommitSHA`) to route the event.
5. **`HUD_ADMIN_TOKEN` is set in `~/.config/loom/hud.env` but the running
   `loomd` (PID 77667, started 2026-05-04) does not have it loaded** — so
   the `/api/webhook/*` endpoints reject every inbound request with
   `403 admin token is not configured`. CI webhooks are effectively dark.
6. **`~/.cache/loom/agent-id-*` accumulates indefinitely.** Pre-cleanup
   today: 269 files (134 older than 7 days, half from sessions that
   have been gone for weeks). No automatic eviction.
7. **Namespace inference bug for `<repo>/.claude/worktrees/<branch>`
   layouts** — fixed in this same commit (see `stripWorktreeFromRepoRoot`
   + bash equivalent in `hookNamespaceVars`). Was producing nonsensical
   namespaces like `worktrees/competent-allen-d7252d/claude/competent-allen-d7252d`.

## What's already in place (don't rebuild)

- `loom agent {session-start,session-end,heartbeat,keepalive,task-sync,
  hook-status,event-emit}` CLI surface — covers 90% of what a hook
  needs to call.
- `pkg/generator/templates/hooks/{codex.toml,generic.json}.tmpl` — EPIC 3
  CONFIG-1/2/4 already moved hook bodies into Go templates. Adding a
  shared bootstrap fragment is a small extension, not a rewrite.
- `internal/hud/domain/webhook/` — full GitLab + GitHub webhook plumbing,
  with HMAC verification, event log, and EventBus broadcast. Mapper is
  one file (`mapper.go`, 51 lines) so we can extend it.
- `agent_presence_list` + `agent_session_list` — already expose enough
  metadata to find an active session by repo + branch.
- `pkg/eventpub.HTTPPublisher` (Phase 1.3 of spectator plan) — best-effort
  HTTP publisher we can reuse for hook-emitted telemetry.

## Proposed workstreams

### A — Shared bootstrap fragment (1 day)

Add `pkg/generator/templates/hooks/_bootstrap.sh.tmpl` that produces a
single-line shell snippet defining `LOOM_AGENT_ID`, `LOOM_NS_PROJECT`,
`LOOM_NS_BRANCH`, `LOOM_HOOK_LOG`, `LOOM_HOOK_START_NS`. Hooks become
3-line bodies: source the bootstrap, invoke `loom agent <verb>`, log
duration on exit.

Rationale: removes ~400 chars × 17 hooks ≈ 7 KB of duplicated boilerplate
from `~/.claude/settings.json`. Easier to read, easier to fix when a
field name changes (single edit, regen, sync — vs 17 edits).

**Acceptance**: `~/.claude/settings.json` total size drops from ~14 KB
to under 6 KB. Each hook command ≤ 250 chars. All existing hook tests
in `pkg/generator/configs_hooks_test.go` still pass.

### B — Structured hook tracing (1 day)

Each hook emits a single JSON line to a per-day rotated log
`~/.cache/loom/hooks/YYYY-MM-DD.jsonl` with: `{ts, event, agent_id,
session_id, duration_ms, exit_code, command_tail}`. The bootstrap
fragment writes the start/end automatically — hooks themselves don't
need to know.

Add `loom agent hook-trace --tail 20` and `loom agent hook-trace
--since 1h --slow 200ms` for inspection. HUD: surface a "slow hooks"
card in the diagnostics panel reading `~/.cache/loom/hooks/`.

**Acceptance**: hook-trace CLI returns the last N JSONL lines parsed.
HUD diagnostics panel renders a "p95 hook duration" stat per event.

### C — Daemon admin-token hot reload + cache eviction (½ day)

Two unrelated reliability fixes:
- `loomd` re-reads `~/.config/loom/hud.env` on `SIGHUP` so we can
  rotate or set `HUD_ADMIN_TOKEN` without restarting and breaking
  every active agent's keepalive.
- `loomd` startup sweeps `~/.cache/loom/agent-id-*` and
  `~/.cache/loom/parent-session-*` files older than 14 days; logs
  count at debug level. Hourly tick after that.

**Acceptance**: `kill -HUP <loomd-pid>` picks up new env. Cache
file count stays bounded under steady-state agent churn.

### D — CI session-linking (2 days)

Extend `internal/hud/domain/webhook/mapper.go` with a `routeFailureToActiveAgent`
helper that, before falling back to `spawn.Request`, queries
`agent_presence_list` for sessions whose `last_branch` matches
`ev.MergeRequest.SourceBranch` (GitLab) or `ev.CheckSuite.HeadBranch`
(GitHub). When a match is found:

1. Publish `agent.notification` event onto the daemon EventBus with the
   session_id, pipeline_id, and CI failure summary.
2. Send a macOS user notification (via existing `internal/notify` if
   present, else `terminal-notifier`).
3. Optionally insert a system-message hint into the agent's nudge queue
   via `loom agent nudge-queue --add` so the next session start sees a
   "CI failed on your branch" prompt.

Spawn-fresh remains the fallback when no active session matches.

**Acceptance**: a deliberately-failing pipeline on a branch with an
active claude-code session triggers (a) macOS notification on this
machine and (b) `agent.notification` event visible in `/events` SSE
stream. No spawn occurs while the original session is alive.

### E — Documentation + agent-discoverable status (½ day)

- `docs/hooks.md` describing the hook architecture (bootstrap, telemetry
  tier, CI linking, tracing).
- `loom agent hook-doctor` — single-command health check that runs
  `hook-status`, parses `~/.cache/loom/hooks/`, verifies daemon is
  reachable, and prints a colored summary. Suitable for inclusion in
  `loom status` and HUD diagnostics.

## Sequencing & estimates

| Order | Stream | Risk | Est |

| 1 | Workstream C (daemon SIGHUP + cache eviction) | low — additive | 0.5d |

Total: ~5 dev-days for all five streams. Each lands as its own MR.

## Out of scope for this plan

- Migrating hooks away from `bash -c` to a compiled `loom hook-shim`
  binary. Considered but the bootstrap fragment captures most of the
  ergonomic win at 1/10 the work.
- Replacing the Claude Code `~/.claude/settings.json` hook surface with
  a custom MCP transport. Tied to upstream Claude Code roadmap; revisit
  when MCP supports lifecycle hooks natively.
- Auto-pushing nudges from CI failures into running agent input streams.
  Treated as Phase 6 — needs explicit user opt-in given the prompt-injection
  risk surface.

## What this MR ships

Just the namespace inference bug fix (`stripWorktreeFromRepoRoot` helper +
its bash analog in `hookNamespaceVars` + tests for both). Cache cleanup
(269 → 135 files) ran out of band against `~/.cache/loom/`. The five
workstreams above are deferred to their own MRs.
