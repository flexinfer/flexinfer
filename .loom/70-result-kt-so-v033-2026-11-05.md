## What the gate cannot show, and the probe that covers it

The gate's prompts and system prompts already ask for exactly the tool call or JSON envelope the constraint allows.
At temperature 0, the model emits those tokens whether or not a grammar is applied. Both arms produced 9,773 tokens and
3,250 drafts, and MTP acceptance was 99.9 %, so these turns are close to templated.

That is the agent-loop workload the certificate is for. It shows that the bitmask path costs nothing measurable when
it agrees with the model. It cannot show that the grammar was applied at all.

So, before deleting the canary, I sent seven single probes (temperature 0, `max_tokens` 120). In each forced probe the
constraint contradicts what the model says on its own:

| Probe | Request | Reply |
|---|---|---|
| unguided | "Say hello to me in one short sentence." | `Hello!` (3 tokens) |
| `response_format` json_schema, strict: `code` enum `QUUX-7781`, integer `n` in 40–49, no extra properties | same prompt | `{"code": "QUUX-7781", "n": 42}` (29 tokens) |
| `structured_outputs.choice` `[alpha-zulu, omega-yankee]` | same prompt | `alpha-zulu` |
| `structured_outputs.regex` `ZX-[0-9]{4}-QQ` | same prompt | `ZX-0904-QQ` |
| tools + `tool_choice: auto` | "What is 2+2? Answer directly in words, do not use any tool." | `Four`, no tool call |
| tools + `tool_choice: required` | same | `lookup_ticket({"ticket_id": "2+2"})`, finish `tool_calls` |
| tools + named `tool_choice` | same | `lookup_ticket({"ticket_id": "2+2"})`, finish `stop` |

- **No HTTP 500s.** Every reply was 200, with the qwen3 reasoning parser active and thinking off. That covers
  #61574 / #63423: an implicit reasoning end no longer returns a 500, and the grammar starts after the empty think
  block.
- **Spec decode stayed on.** Across the seven probes, drafts went up 56 and accepted tokens 55, out of 112 draft
  tokens, about 49 % acceptance. This is the expected cost when a grammar overrides what the draft head proposes.
  It is reported, not gated.
- **Named `tool_choice` finishes with `stop`, not `tool_calls`.** That is vLLM's OpenAI-compat behaviour for a forced
  named function. The gate's `named` mode already accepts it.

## Backend

`auto` in 0.33 (`sampling_params.py`, read at v0.33.0) picks **xgrammar**. It falls back to **guidance**, or to
**outlines** for schemas guidance cannot handle and for non-tekken Mistral tokenizers. It never picks
`lm-format-enforcer`, which is deprecated in 0.33 and removed in 0.35.

The image ships xgrammar 0.2.8, llguidance 1.7.6, outlines_core 0.2.14 and lm-format-enforcer 0.11.3. The engine logs
no per-request backend. The gate's schemas and the probes above are plain JSON Schema, choice and regex, all of which
xgrammar supports.

The controller only ever renders `{"backend":"auto"}` (`structuredOutputsBackendAuto`), so the certificate can never
select lm-format-enforcer.
