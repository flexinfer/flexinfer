A synchronous request to a shared-GPU lane no longer waits for its client's timeout when the lane holding the card releases it to a different, higher-priority lane. The proxy took any standing release on the holder to mean the card was coming back to the waiting lane, and checked only once at the preempted wait, so after each release that handed the card to the job runner's next job the requests that arrived around it were held until the client gave up (KT-JOBS 2026-11-20: two windows of about a minute, alternate requests held to 120 s). A released holder now counts as handing the card back only when no other member with a strictly higher priority wants it, and a request to a lane the election set aside checks again every 5 s while it waits for the card.
