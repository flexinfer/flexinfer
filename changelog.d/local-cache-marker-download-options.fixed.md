A `strategy: Local` cache staged from `HF://` now re-stages when the files it must hold change. The stage Job's completion marker was `sha256(spec.source)`, so a `ggufFile` rename, an `mmproj`, `hfAllowPatterns` or `hfIgnorePatterns` change, or an `hfRevision` bump recreated the `<model>-cache-stage` Job only for it to find the old marker, exit "already cached", and leave the serving pod looking for a file the node did not have. On 2026-10-24 the upstream rename of the Glimmer GGUF could only be promoted on `muse-glimmer-30b-tools` by removing that marker on `cblevins-5930k` by hand. The marker now hashes `spec.source` together with the resolved allow patterns, ignore patterns and revision.

Existing caches are not re-downloaded fleet-wide. A stage Job that finds only the old source-keyed marker adopts it without downloading when the files on disk still satisfy the current options: the directory holds files, every `ggufFile` and relative `mmproj` is present and non-empty, every allow pattern matches a staged file, and, with `hfRevision` set, huggingface_hub's download metadata records that commit for every staged file. Adoption renames the old marker, so it happens once. A cache that fails any check is wiped and downloaded, and the Job log names the check. Stage Jobs only run on a new Model, a generation change or an unready cache, so the controller roll itself starts none.

The stage Job also carries a `flexinfer.ai/cache-marker` annotation. A finished Job lingers for its 300 s TTL, and an option change inside that window used to read the old Job's success as the new file set staged; such a Job is now deleted (foreground, so a running download cannot overlap the next wipe) and the cache reports `re-staging local cache: download options changed`. Jobs from before this change carry no annotation and are read as before.

The pvc-source Local stage and the SharedPVC copy Job are unchanged: their marker is keyed on a `pvc://` source whose path already names the file set. The SharedPVC `HF://` prefetch Job is not covered here; its marker carries no hash at all and the Job is recreated only on a `spec.source` change.
