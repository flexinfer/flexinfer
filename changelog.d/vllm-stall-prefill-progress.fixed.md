- The vLLM stall detector (controller, in-pod runtime manager and the exec readiness probe) now counts a change in the KV-cache usage gauge (`vllm:kv_cache_usage_perc`, or the older `vllm:gpu_cache_usage_perc`) as progress. vLLM counts prompt tokens only when a prefill completes, so a chunked prefill longer than `stallWindow` (default 5 min) looked like a hung engine. On 2026-11-21 the controller deleted a 128K canary mid-way through a 120K-token prefill while the gauge rose from 0.17 to 0.74. A hung engine still freezes the gauge with the counters. The gauge is optional, and a bad value in it is ignored. Takes effect at the next controller repin (the probe change restarts dedicated vLLM lanes once) and, for in-pod lanes, with a runtime image that carries it.
