The vLLM plugins now load on 0.33.0 as well as 0.32.0 (text plugin 0.10.0, plugin-common 0.3.0), and carry two opt-in gfx1100 tuning paths. The text plugin's MTP `hf_config_override` wrapper takes 0.33's extra `transformers_mtp_overrides` argument, which 0.33 passes positionally and through `functools.partial`; before this, every MTP lane on a 0.33 image raised a TypeError while building its draft config. `FLEXINFER_SEGMENTED_RUNTIME_TABLES=1` makes the `ROCM_SEGMENTED_ATTN` autotune build its block tables at the model runner's width and compile each tuned winner at that width after tuning, so live requests stop compiling the segmented kernels on first use (gap G7). `FLEXINFER_FLA_AUTOTUNE=relaxed` prunes only the 4+-stage FLA/GDN autotune configs and leaves the rest to Triton's autotune (gap G10). With neither variable set, behaviour is unchanged, except for two new fields in the plugin's boot log line. `verify_vllm_gfx1100_native_w4a16.py` now fails the image build if the segmented patch cannot install on its vLLM.
