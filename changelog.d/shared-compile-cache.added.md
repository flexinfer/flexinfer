`spec.cache.compilationCache.scope: Image` is a new, opt-in compile-cache layout. Lanes on one node, image digest and GPU arch share one directory, `<hostPath>/shared/<gpuArch>/<digest12>/`, instead of keeping one cache each under `<hostPath>/<namespace>/<model>/` (research serving-gaps C5, slice 5). Triton, TorchInductor, vLLM, MIOpen and comgr key their entries by source, options, toolchain, GPU and shapes, and vLLM keys torch.compile output by a config hash, so lanes on the same image reuse each other's kernels and segmented-attention autotune tables while different models keep separate subtrees. Today a canary or probe compiles from scratch and stores a full copy, and seeding a new lane meant a manual `cp -a` on the node. On 2026-10-30 the per-lane caches held about 35 GB on the 7900 XTX node and 31 GB on the 5930k.

- `compilationCache.seedFrom` copies a node directory, normally the lane's earlier per-Model cache, into an unseeded image-scoped cache once. A `compile-cache-prepare` init container stages the copy on the cache mount and hard-links it into place without replacing entries, so lanes already using the directory never see a half-copied file.
- The same init container guards against vLLM's one unsafe writer: `vllm_compile_cache.py` is written with a plain `open`/`write` and parsed with no fallback, so a write cut short would crash every lane with that config hash. An index that does not end in `}` is renamed aside and that config recompiles once.
- The runtime path: a runtime profile with `sharedCompileCache: true` mounts the image-scoped directory of its own digest at `/cache/compile`, and the runtime manager re-points an `Image`-scoped load's cache env there, with the same guard. The payload carries `FLEXINFER_COMPILE_CACHE_SCOPE=Image` beside the per-Model env, so a runtime without the mount keeps the per-Model directory.
- An image that is not digest-pinned, or an unknown GPU arch, falls back to the per-Model directory.

The default scope renders byte-identical pod templates and runtime load payloads, so the controller roll restarts no lane. `controllers/live_lane_render_test.go` pins the pod templates of seven live lanes, rendered by master `4fd5efa0` before this change. No runtime profile and no `deploy/models` lane opts in yet.
