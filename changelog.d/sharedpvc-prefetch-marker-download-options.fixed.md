A `strategy: SharedPVC` cache fetched from `HF://` now re-fetches when the files it must hold change. The `<model>-cache-prefetch` Job wrote a bare `/models/<model>/.flexinfer_cached` marker and exited "already cached" whenever it found one. It was recreated only on a `spec.source` change, and even then it found the same marker. So a `ggufFile` rename, an `mmproj`, `hfAllowPatterns` or `hfIgnorePatterns` change, an `hfRevision` bump or a new source never reached the PVC, and `docs/user/quantization.md` told operators to clear the PVC by hand. The marker is now `.flexinfer_cached_<sha256>`, keyed like the Local stage marker on `spec.source` plus the resolved allow patterns, ignore patterns and revision.

The prefetch Job never expires, so it now carries `flexinfer.ai/cache-marker`. A Job built for other options is replaced and the cache reports `re-fetching shared cache: source or download options changed`. A finished Job is replaced in the same pass. A running one is deleted in the foreground and waited for. A quantized lane's `<model>-quantize` Job and `status.cache.quantization` are cleared first, so the new file set is quantized again. The directory is still not wiped: `snapshot_download` fetches only the files whose download metadata or hash disagrees with the repo. The Job now also refuses to write its marker when a `ggufFile` or relative `mmproj` is missing after the download.

Existing caches are not re-downloaded fleet-wide. Prefetch Jobs from before this change have no marker annotation, so the controller rebuilds their marker from the download options in their env and leaves a current one alone; the roll starts no Job. The first new Job for a lane adopts the bare marker without downloading when the files still satisfy the current options. The directory must hold files, every `ggufFile` and relative `mmproj` must be present and non-empty, and every allow pattern must match a file on disk or one huggingface_hub recorded downloading. With `hfRevision` set, every huggingface_hub download record must name that commit. The check reads those records rather than the directory listing because a quantizer may have deleted the downloaded weights and written its own output beside them. A Job that replaced one built for another `spec.source` never adopts the bare marker. Either way the first new Job consumes the bare marker, and a cache it does not adopt falls through to the incremental download. The MLC git clone ignores the download options and keeps the bare marker.
