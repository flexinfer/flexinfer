Add two opt-in KV-pool levers to the FlexInfer vLLM plugins (plugin-common 0.5.0, text plugin 0.12.0), both off unless a lane sets the env flag. `FLEXINFER_EMBED_HOST=1` (S7) serves the target model's input-embedding table from mapped host memory: it wraps `BaseModelLoader.load_model` inside the model runner's memory-profiling window, copies each untied `embed_tokens` table to exact-size `cudaHostAlloc` memory through vLLM's `get_accelerator_view_from_cpu_tensor`, spot-checks the mapped rows and frees the device copy, so vLLM sizes the KV pool with the saving (2.37 GiB on Qwen3.8-27B); the MTP draft shares the module. `FLEXINFER_SEGMENTED_FP8_GFX11=1` (G3) lets `ROCM_SEGMENTED_ATTN` serve an `fp8_e4m3` KV cache on gfx11: it wraps vLLM 0.32/0.33's three gfx12-only checks (backend selection, impl constructor, op dispatcher) so that, for an fp8 cache on gfx11 only, `on_gfx12x` answers like `on_gfx1x` during the call, and it logs how many fp8 dispatches took the segmented kernel. The native-W4A16 build verifier installs the embed-host patch at build time and checks the names the fp8 gate lift wraps from source. Canaries: matrix rows `xtx-s7-embed-host-2026-11-05` and `xtx-g3-segmented-fp8-gfx11-2026-11-05`.
