- Populate `status.cache.sizeBytes` on the v1alpha2 `Model`. It was assigned a literal `0` at every site, so the capacity tooling added alongside `spec.cache.prefetch` had nothing to sum: `flexinfer cache capacity` printed `STAGED` as `-` with a `+N?` suffix, and on a live fleet *every* model fell into that unknown bucket — which is precisely the question a capacity report exists to answer. Each cache job now measures what it staged and reports it through the container termination message, the same channel quantization jobs already use, and the controller records it. This covers all six job kinds — shared-PVC copy and HF prefetch, PVC-source check, and the node-local stage, HF stage, and check jobs — so `Local` (hostPath) caches, the majority of a typical fleet, report sizes too. The measurement is block usage (`du -sk`, POSIX so it works on the busybox and Debian images these jobs run on) of the model's own directory, so per-model sizes on a shared PVC sum without double-counting.

- Carry `status.cache.sizeBytes` across reconciles. A staging Job and its pods are garbage-collected within minutes of completing, but the weights they staged are not, so re-deriving the size later is impossible; the paths that rebuild `CacheStatus` from scratch now preserve it, and a success the controller cannot measure keeps the recorded value instead of zeroing it. `0` means unknown, never empty — a cache staged before this reporting existed, or populated out of band on a node, stays honestly unknown until its cache job next runs.

- `flexinfer cache capacity` now reports a size per node-local cache and a total for them, with the same `+N?` unknown count the PVC table uses. Previously node-local caches were listed by name and strategy only, with no indication of the disk they occupy.
