### Fixed
- **LLM-judged gates retry on unparseable judge output instead of escalating immediately (M2.5)** (`pkg/mills/clients/flexinfer.go`, `pkg/mills/clients/flexinfer_test.go`, `pkg/mills/gates/llm_judge.go`, `pkg/mills/gates/llm_judge_test.go`, `pkg/mills/pipeline/runner_test.go`): the `spec_conformance` / `pr_self_review` gates previously bubbled a parse error from `parseRubricEnvelope` ("no parseable score envelope in response") up through `gates.Registry.EvaluateAll` and `pipeline.Runner.Drive`, hitting the no-retry escalation branch at `runner.go:276`. Live regression on 2026-05-16 canary `PIPE-MILLS-CANARY-M1D-VERIFY-2`: gemma4-26b returned free-text ("please provide the diff…") and the entire pipeline escalated on the first `spec_conformance` call even though every prior stage succeeded. New `ErrRubricUnparseable` sentinel (plus a `*rubricParseError` wrapper exposing the `IsRubricUnparseable() bool` duck-typed predicate) lets `LLMGate.Evaluate` translate a parse miss into `Outcome{Pass:false, JudgedBy:"flexinfer:unparseable"}` with `err=nil`, so the runner's existing gate-retry path (rewind to `RetryFrom`, bump attempt counter, re-run `pr_self_review`) fires naturally. Transport failures (network, timeout, 5xx) still surface as errors and still escalate — only the "judge ran but answer wasn't graded" path was reclassified. New tests: `TestLLMGate_UnparseableJudgeReturnsSoftFailNotError`, `TestLLMGate_DuckTypedUnparseableErrorAlsoSoftFails`, `TestLLMGate_TransportErrorStillEscalates`, `TestParseRubricEnvelope_WrapsSentinelOnNoJSON`, `TestParseRubricEnvelope_WrapsSentinelOnOutOfRangeScore`, `TestRubricJudge_UnparseableContentExposesPredicateAcrossWrap`, `TestRunner_LLMGateUnparseableOutcomeTriggersRetry`.
- **HUD stale-session reaper ignored spawn pods that registered presence without heartbeating** (`internal/hud/monitor/fleet.go`, `internal/hud/monitor/fleet_test.go`): `fleetStaleSessionReapAfter` (10min) failed to fire on spawn agents whose presence rows carried `LastHeartbeat=""` — visible in the HUD as `spawn-claude-code-*` rows stuck in `STATUS=active` with `HEARTBEAT=---` long after the spawn pod died. Root cause: `fleetview.AgeSeconds` clamps empty / unparseable timestamps to `0`, and the reaper's lookup table seeded `heartbeatBySession[s.ID] = 0` for these rows. Age 0 < 600s threshold ⇒ session never reaped ⇒ immortal "active" session. Fix: skip presence rows with empty `LastHeartbeat` when seeding the heartbeat maps so the reaper falls through to its `session.StartedAt` clock, which is the documented semantic for "presence exists but never reported liveness." Regression test `TestFleetMonitor_StaleSessionReaper_EmptyHeartbeatFallsBackToSessionAge` pins the scenario: active session + presence row with `last_heartbeat=""` + `started_at=20min ago` must end up reaped.
- **HUD traces filter resolves to root agent for subagent rows** (`internal/hud/frontend/src/lib/components/fleet/FleetTable.svelte`, `internal/hud/frontend/src/lib/components/TracesPanel.svelte`): Fleet table's "Traces" button passed the row's own `agent_id`. For subagent rows (Claude Code Task-tool children like `claude-code-NNN-MMM`), the audit stream had nothing under that id because subagents share their parent's MCP session — their tool calls are recorded under the *root* agent's id. So `entry.agent_id === agentFilter` never matched. Now resolves to `row.rootSession.agent_id` when the row is a child. TracesPanel's empty state distinguishes "no traces matched a filtered agent" (with a hint about subagent sharing) from "no traces in the stream at all."
- **HUD Live Agents: stale ORPHAN badge alongside SESSION evidence + cramped "no active session match" divider** (`internal/hud/frontend/src/lib/utils/agents.ts`, `internal/hud/frontend/src/lib/components/fleet/FleetTable.svelte`): agents with a locally-matched live session were rendering the `ORPHAN` evidence pill even though the SESSION pill was lit, when raw presence/session data arrived at the client out of order (a snapshot could carry `agent.is_orphan=true` alongside a now-matching session because raw presence was sampled before the session existed). The client's `buildUnifiedAgents` trusted the server's `is_orphan` flag unconditionally while computing `has_session` locally — the two could disagree. Now the client mirrors the server's `markOrphan` invariant ("orphan ⇒ no active session"): when the client determines `has_session=true`, `is_orphan` is forced to false regardless of the snapshot flag. The same clear is applied in the session-matching second pass. The "No active session match" divider label was also absolutely positioned with `top: -6px`, so it visually overlapped the row above; relayed as an inline-block pill below the dashed border instead. `pnpm build` clean; `go test ./internal/hud/fleetview/...` green (existing `TestOrphan_StalePresenceWithoutSessionIsOrphan` covers the server-side invariant).
